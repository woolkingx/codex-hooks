Handbook Skills

1. Principle

A handbook skill is a posture for reading, writing, or verifying architecture truth. It does not replace runtime skill files and does not edit runtime behavior by implication.

2. Postures

posturejoboutput
readerFind the source-of-truth chapter and explain the model.Owning chapter, topology node, schema owner, and gate.
writerApply principle, topology, formal mapping, worked path, anti-pattern, and gate.Updated handbook section with one canonical owner.
verifierCheck links, parse, vocabulary, forbidden framing, and scope.Evidence and remaining gaps.

3. Input and Output Contract

inputUser request, current handbook chapter, related schema, related plan.
outputUpdated handbook section, updated index link, gate, verification evidence.
boundaryNo runtime skill, schema, policy, or code edit unless the user asks for that layer.

4. Reusable Prompt Shape

Given a codex-hooks handbook chapter, identify:
1. principle
2. topology nodes and owners
3. SDU / PCI / next-PDU mapping
4. worked requirement path
5. anti-pattern
6. acceptance gate

If one is missing, repair only the handbook owner section.

5. Gate

GATE-HANDBOOK-SKILLS-01: every handbook edit must declare posture, source chapter, output section, and verification command.
