Artifact Roles

1. Principle

Every durable claim has one owner. Drift starts when handbook, CLAUDE, schema, policy, skill, and runtime files all try to own the same truth.

2. Role Map

3. Migration Rule

Move architecture claims into the handbook first. Then trim boot cards, skills, plans, and runtime docs to point at the owner. Do not delete source material until the owning handbook section and verification gate exist.

4. Anti-pattern

CLAUDE.md owns architecture
skill owns product doctrine
schema owns hidden runtime behavior
runtime code repairs missing schema truth

This makes the actor own truth. codex-hooks keeps truth in handbook and schemas, then projects it into plans, skills, policy files, runtime code, and tests.

5. Gate

GATE-ARTIFACT-01: every durable architecture claim must have exactly one canonical handbook owner and no competing owner in CLAUDE, skill, schema, policy, or runtime files.
