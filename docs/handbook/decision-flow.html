Flow

1. Two Paths

pathuses modelpurpose
authoring compileryes (skill-driven)Turn policy/user.json requirements into rule data; write compiler observations to log.
hook runtimenoLayer executor evaluates PCI deterministically against SDU; produces next-PDU.

2. Authoring Compiler Flow

policy/user.json requirements[]
  -> codex-hooks compiler skill (model-driven)
  -> read event input schema, rule schema, and output schema
  -> emit one rule.json per requirement id
  -> write compile.gap / trace / explain / diagnostic as log records
  -> verify: rule validates against event rule schema

The compiler is invoked outside the hot path. The skill (skills/codex-hooks/) declares the contract; the emitted artifact is plain JSON that can be diffed, reviewed, rolled back, and executed without a model.

3. Hook Runtime Flow (Layer Executor)

raw hook input
  -> SDU                        ensureValid against channel input schema      (throw on violation)
  -> load rules                  policy/rules/<event>/*.rule.json
  -> for each rule by priority:
       evaluate trigger path values
       evaluate admitted feature modules
       first matching rule output wins
  -> next-PDU value | null       ensureValid against channel output schema    (throw on violation)
  -> project to wire             stdout JSON or no output

4. Example: pre-tool-use rm denial

SDU value:
  { hook_event_name: "pre-tool-use",
    tool_name: "Bash",
    tool_input: { command: "rm -rf tmp" },
    cwd: "/home/user/repo", session_id: "s1", ... }

rule PCI:
  trigger["$.tool_name"] = "Bash"
  feature["bash-command"].value = {
    path: "$.tool_input.command",
    name: "rm"
  }
  output = { decision: "block",
             reason: "rm denied",
             hookSpecificOutput: {
               hookEventName: "PreToolUse",
               permissionDecision: "deny",
               permissionDecisionReason: "rm denied" } }

applyRule walk:
  resolveInput("$.tool_name", SDU) -> "Bash"
  trigger compare -> true
  bash-command feature reads "$.tool_input.command" -> "rm -rf tmp"
  bash-command feature parses privately and matches name "rm" -> true
  return rule.output

next-PDU (validated):
  { decision: "block", reason: "rm denied",
    hookSpecificOutput: { hookEventName: "PreToolUse",
                          permissionDecision: "deny",
                          permissionDecisionReason: "rm denied" } }

wire: stdout JSON

5. Error Flow

boundaryon violation
input validatethrow (schema boundary) → executor catches → log + stderr + non-zero exit; fail-closed may emit an official output branch when the event output schema admits one.
rule load (event rule schema)throw at load time.
feature handler contract failurepropagated; executor catches and records a log entry. Domain parser misses inside total feature handlers return no-match.
next-PDU validatethrow; reported as above.

No silent catch anywhere. fail_closed selects the shape of the error next-PDU but does not change reporting. Errors are runtime log information unless the official event output schema admits an error output branch.

Error path (fail-closed projection through event owner)

caught throw in runOnce()
  -> loadHandler(rawInput.hook_event_name)
       known   -> failClosedOutput(meta, error) shaped per meta.id / meta.output_actions
                  -> ensureValid(output, official next-PDU schema)
                  -> return runtime result with output when official schema admits it; error details stay log information
       unknown -> return { ..., output: null, error: toErrorPDU(...) }
  -> CLI writes stdout if output != null
  -> CLI writes stderr + non-zero exit on logged error information

Unknown event has no official output owner: the runtime reports the error as log information and does not invent a custom output. The executor refuses to build output data from no event schema.
