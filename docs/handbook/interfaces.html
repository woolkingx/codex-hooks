Interfaces

interfacev1 statuscontract
hookrequiredRead one official Codex hook JSON object from stdin and write one official Codex hook JSON output to stdout.
clirequiredRun fixtures through the same schema-transition path. CLI must not invent hook semantics or emit non-official fields in hook wire output.
policy compilertargetCompile policy/user.json requirements into one rule file per id; write feedback to logs.
deploy cliimplementedRender official Codex hook config; run deployment doctor checks; produce a dry-run install plan, or write hooks.json with backup when --apply is set.
daemonroadmapFuture Unix socket manager using the same core for hot reload, shared state, and central management.
admin apiroadmapFuture MCP or local HTTP API for policy CRUD, status, logs, and policy packs.

Target Compiler CLI

codex-hooks policy requirements list|validate [--file policy/user.json]
codex-hooks policy compile    [--user policy/user.json] [--out policy/rules]
codex-hooks logs              [--log hooks.jsonl] [--tail 20]

These commands are architecture targets. Compiler failure, gap, trace, explain, and diagnostic output belongs to log data.

V1 Runtime Rule

V1 has no daemon, no socket, no background state, and no hot reload.
Every hook invocation is a fresh process.
Rules reload at process start.
The manager core must remain daemon-ready.
V1 hook stdout contains only official Codex hook output fields.
