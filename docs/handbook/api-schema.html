Permission mode is not a uniform runtime helper. It is an input field whose meaning depends on the event's official output power. Each event owner must decide using only output fields admitted by its own official output schema.

Shape Rules

input.hook_event_name = event const
input.additionalProperties = false
output.additionalProperties = false
output = common envelope + event-specific hookSpecificOutput
event_owner = dispatch by hook_event_name
validation_projection = strip upstream default annotations

Each official schema pair defines one event owner boundary. Runtime orchestration must dispatch to the event owner before producing the official output shape.

Hook stdout is official output only. Runtime internals such as normalized events, policy decisions, status, or logs must not appear in hook stdout unless translated into fields allowed by that event's official output schema.

Every policy action must project into an official output branch for the active event. Unsupported branches fail closed at the event owner; they are not omitted and are never serialized as custom fields.

The mirror files stay raw. API validation uses a local projection that removes upstream default annotations before passing schemas to schema2object, because upstream defaults are annotations while schema2object treats defaults as runtime values.

Event Runtime Surface

src/events/<event>/<event>.mjs
src/events/<event>/<event>.rule.schema.json
src/events/<event>/test.mjs
src/events/<event>/CLAUDE.md

The official input and output schemas are the event wire data contracts. The local event rule schema owns trigger + feature + output rule data. Feature value schemas live with feature modules and are admitted by event rule schemas. No owner.json, event meta schema, or central registry schema becomes a fourth event data object.
