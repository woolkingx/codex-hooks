Stage Actions

1. Principle

A stage is an action boundary, not an agent identity. A human, model skill, CLI, or test may execute the stage, but the stage decides the artifact and the artifact decides the gate.

policy/user.json requirement
  -> input schema (SDU)
  -> rule schema (trigger + feature + output data)
  -> output schema (next-PDU)
  -> event executor
  -> evidence

3. Action Rule

Do not choose a tool, model, or runtime path before naming the stage. The stage names the owner. The owner names the schema. The schema names the legal transition. The gate proves the transition.

4. Anti-pattern

agent -> tool -> helper schema -> fake data root

This order makes the actor own truth. codex-hooks uses:

input data --(rule data)--> output data

5. Gate

GATE-STAGE-ACTIONS-01: every requirement-to-rule action must name stage, input artifact, output artifact, owner, gate, and failure route before execution.
