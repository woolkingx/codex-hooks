Acceptance Gates

Gates follow data ontology. A schema is accepted only after the owned data object is named.

gatestatusproof
GATE-DATA-ONTOLOGY-01acceptedBefore adding any schema, name the data object, owner, lifecycle, reader, writer, and why it is not already event input, event rule, event output, log, status, config, deploy, profile, tools, or user requirement data.
GATE-SCHEMA-TREE-ROOT-01acceptedEvery active schema resolves from schema/codex-hooks.schema.json through Loader.resolve(); runtime code does not compose synthetic schemas or bypass returned sub-loader scope.
GATE-TOOLS-OBJECT-TREE-01acceptedtools.schema owns the external callable object tree: type, status, value descriptors, methods, owner references, adapter exposure, schema references, and gates. It must not own event transition logic, feature behavior, policy semantics, runtime state, or deploy side effects.
GATE-EVENT-TRIPLE-01acceptedEach event runtime exposes only input schema, rule schema, output schema, and executor. No event meta schema, event PDU, derived-field schema, or decision schema root.
GATE-RULE-TRIGGER-FEATURE-01acceptedRule schema defines the only runtime rule data: trigger path values, admitted feature module data, and official output data. Runtime rejects fields/conditions/process/params/write rule data.
GATE-LOG-ONTOLOGY-01acceptedCompiler gap, report, trace, explain, diagnostic, and runtime errors are log information. No separate gap schema, explain schema, trace schema, diagnostic schema, or error root schema.
GATE-FEATURE-MODULE-01acceptedFeatures are module-owned functions with module-owned schemas under src/features/<feature>/. A callable feature may have a descriptor under tools.schema, but that descriptor does not own feature behavior. Persisted feature parameters live under rule.feature.<name>.
GATE-HOOK-STATE-01acceptedHook runtime control state is owned by status/hook-state, keyed first by normalized cwd as project context, bounded by TTL and caps, and never stored in policy, rule files, event input/output, or logs.
GATE-BLOCK-FIRST-TIME-01acceptedblock-first-time blocks once per cwd + session_id + compact_mark + feature key; PostCompact advances compact mark and resets the effective first-time status, while repeated compact turn_id values are idempotent.
GATE-USER-AUTHORING-01acceptedpolicy/user.json is user requirement data and compiler input. It is not event runtime data and must not contain rule clauses, feature config, diagnostics, traces, or runtime config.
GATE-RULE-RUNTIME-01acceptedpolicy/rules/<event>/<id>.rule.json is the only persistent compiler output required by runtime. If compilation fails, the compiler writes log information and exits non-zero.
GATE-USER-RULE-SYNC-01acceptedpolicy/user.json and policy/rules/<event>/<id>.rule.json are a bidirectional invariant. Verification fails on missing rules, orphan rules, id mismatch, event mismatch, enabled mismatch, invalid JSON, or invalid rule schema.
GATE-POLICY-AUTOMATION-01acceptedPolicy changes enter through policy/user.json mutation commands, runtime rule files are reconciled as compiler projections, and focused probes prove the changed command behavior before the full release gate.
GATE-OWNER-INTERFACE-01acceptedCLI and CI/CD pipelines may compose owner operations, but mutation and validation logic must live in the owning module rather than in shell scripts or adapter-specific branches.
GATE-GITLAB-CONTROL-01acceptedgit remote -v has gitlab as the normal publish target; GitHub and Codeberg are not local publish targets unless the user explicitly overrides the boundary.
GATE-RELEASE-PUBLISH-01acceptedGitLab protected branches include release; GitLab remote mirrors are disabled; GitHub and Codeberg repository release SHAs change only after the protected release manual approval job runs.
GATE-WIKI-PROJECTION-01acceptedGitLab CI on protected release generates wiki pages from docs/handbook/*.html; GitLab wiki pages publish automatically before public approval; GitHub and Codeberg wiki publish jobs run only after the manual approval gate and contain Home.md and _Sidebar.md.
GATE-DOC-01acceptedHandbook links resolve; index parses; forbidden pseudo-schema vocabulary is absent from canonical paths.
GATE-PUBLIC-01acceptedPublic release shell has README, LICENSE, CHANGELOG, package metadata, CI, examples, security policy, contribution guide, and repo-local npm run verify.
