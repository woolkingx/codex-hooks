Deployment

Deploy Owner

deploy
|- target: user, project, managed, plugin, dry-run
|- environment: platform, cwd, git root, codex home, node, package root
|- artifact: bin command, package root, version
|- hook_config: generated official Codex hooks config
|- validation: schema, policy source, rule files, event coverage, config syntax
|- installation: destination, backup, mode, write plan
`- doctor: checks, warnings, failures

deploy owns install-time data. Runtime config decides which rule files to load after a hook starts; deploy decides whether this tool can be installed safely into a Codex hook layer and what would be written there.

V1 Contract

serviceowner datawrite behavior
render-hooksdeploy.hook_configPure generation only. It returns official Codex hooks config and writes nothing. The default log side-channel is logs/codex-hooks.jsonl; --log may override it.
doctordeploy.environment, deploy.validation, deploy.doctorRead-only checks for Node, bin command, policy paths, user-rule sync, Codex config target, schema reachability, and event coverage.
installdeploy.installationDry-run by default. Real writes require explicit --apply and keep a backup when replacing an existing hooks config.
hook commanddeploy.environment.cwdRuntime command must not depend on the process cwd. Repo-owned schemas resolve from module paths; user-selected policy paths resolve from configured command arguments.

Codex Hooks Config

Codex reads hook configuration from a user or project hooks JSON file. In this repo and the current local runtime, the file is named hooks.json:

scopepathowner
user$CODEX_HOME/hooks.json or ~/.codex/hooks.jsonCodex user config layer. codex-hooks install --target user --apply writes this file with backup.
project<git-root>/.codex/hooks.jsonProject-local Codex config layer. codex-hooks install --target project --apply writes this file with backup.

The generated JSON shape is official Codex hook config data. Each top-level key is a Codex hook event name. Each event maps to matcher groups, and each matcher group contains command hooks.

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "*",
        "hooks": [
          {
            "type": "command",
            "command": "node \"/path/to/codex-hooks/src/adapters/cli.mjs\" hook --rules \"policy/rules\" --log \"logs/codex-hooks.jsonl\"",
            "timeout": 30,
            "statusMessage": "codex-hooks PreToolUse"
          }
        ]
      }
    ]
  }
}
fieldmeaningcodex-hooks behavior
hooksRoot object containing event hook entries.Generated by render-hooks and written by install --apply.
PreToolUse, PostToolUse, etc.Official Codex hook event names.Generated for every event owner registered in src/core/handlers.mjs.
matcherCodex event matcher string.Defaults to *.
typeHook handler type.Always command in V1.
commandShell command Codex executes for the hook event.Calls codex-hooks hook with the selected --rules, optional --profile, and project-local --log. Default log path is logs/codex-hooks.jsonl.
timeoutHook command timeout in seconds.Defaults to 30.
statusMessageStatus text Codex may show while the hook runs.Generated as codex-hooks <EventName>.

Do not hand-edit generated hooks config as the primary workflow. Tell Codex the desired install or hook behavior; Codex should run doctor, render or dry-run install, then write the config only when requested.
