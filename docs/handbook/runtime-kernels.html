Runtime Kernels

Kernel Role

Kernels turn schema-owned data into legal runtime objects. They are not business logic owners.

schema-owned data
  -> schema2object object/fn
  -> feature handler
  -> next schema-owned data

Use Rules

schema2object = root Loader + resolve(ref) + ObjectTree binding
bashjsast     = Bash AST parser (feature-handler private)
AJV           = not used
ad hoc JSON path code = avoid when schema2object can own the path

The runtime creates one root Loader from schema/codex-hooks.schema.json. Schema access goes through resolve(ref); callers must preserve the returned sub-loader and bind data with ObjectTree(data, node, subLoader) or validate with that sub-loader. Runtime code must not compose synthetic schemas or bypass the root tree by reading schema files directly.

Layer executors should not hand-roll field extraction when schema2object can materialize a schema-bound object. Bash parsing is feature-handler internal: rule data may configure a module-owned feature, but bashjsast does not become a data field or schema root. Bash command features are total functions: parser failure means the feature does not match; schema, rule-load, and output-boundary failures remain throws.
