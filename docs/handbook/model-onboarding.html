Model Onboarding

1. Purpose

This chapter is the fast path for a model entering the project. The goal is to route a natural-language user request to the correct owner, schema, boundary, files, and verification command without re-deriving the architecture.

request -> task type -> owner chapter -> schema/data owner -> files -> verification -> report evidence

2. First Read

  1. Read CLAUDE.md for local execution rules and navigation.
  2. Read index.html summary, system map, and chapter map.
  3. Read usage.html to understand that humans state requirements and Codex operates the system.
  4. Pick one task row from the routing table below.
  5. Before editing, name the data owner, schema owner, boundary, and verification gate.

4. Non-Negotiable Rules

  • Do not start from service names. Start from data, schema, owner, and boundary.
  • Do not create schema roots for traces, reports, gaps, diagnostics, or temporary compiler output. They are log information.
  • Do not add rule syntax outside trigger + feature + output.
  • Do not make users hand-edit JSON as the product path. Humans state requirements; Codex operates artifacts.
  • Do not let hook stdout contain non-official fields.
  • Do not install hooks without doctor or dry-run evidence unless the user explicitly accepts the risk.

5. Verification Commands

npm run check:handbook
npm run check:stale
node src/adapters/cli.mjs policy requirements sync --file policy/user.json --rules policy/rules
node src/adapters/cli.mjs run test/fixtures/pre-tool-use-bash-rm.json --rules policy/rules
npm run verify

Use focused commands while editing. Use npm run verify before claiming the system is aligned or ready.
